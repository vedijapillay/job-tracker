Reviewer guide: how to test Job Tracker

For Google’s OAuth verification team · Project job-tracker-510316

Job Tracker is a free, open-source job application tracker that runs on the user’s own computer. It has one Google feature: an optional, read-only Gmail scan that finds job-application emails and suggests tracker entries that the user reviews. Because the app runs locally, there is no hosted version to open in a browser. This page explains how to run it and see that feature work. It takes about 10 minutes.

The permission requested

  • https://www.googleapis.com/auth/gmail.readonly (“View your email messages and settings”). No other scope is requested.
  • Why this scope: the app finds job emails with Gmail’s search query (users.messages.list with q), which Google documents as unavailable with gmail.metadata, and it needs the message text, which gmail.metadata excludes, to tell confirmations, interviews, offers and rejections apart and to read the company and job title.
  • Read-only: the app never sends, changes or deletes email, so there is no write or delete behaviour to demonstrate.

Steps

  1. Install Node.js version 20.17 or newer.
  2. In a terminal, run: 
    git clone https://github.com/vedijapillay/job-tracker.git
cd job-tracker
npm run setup
npm start
  3. Open http://localhost:3000 in a browser. The tracker is empty.
  4. Click Scan Gmail. The first time, this opens the Connect Gmail guide. (A Gmail setup link beside the button reopens it.)
  5. Enter the Client ID and Client secret of the Web application OAuth client in Google Cloud project job-tracker-510316, then click Save and test. It should report that Google accepted the credentials. The redirect address http://localhost:3000/api/gmail/auth/callback is registered on that client. The developer will provide the secret through the verification channel.
  6. Click Scan Gmail again. You are sent to Google to sign in with any Google account, then to the consent screen showing the single permission above. Click Allow. (If an “unverified app” screen appears first, choose Advanced, then continue.)
  7. You return to the app and the scan runs. A window lists the job emails it found: the company, job title, the status it detected, and the email’s subject, date and sender. Nothing is saved until you choose to.
  8. Click Add to Tracker (or Update status for a job already tracked) on a result. It appears in the dashboard behind the window. Not a job email dismisses a result for good.
  9. To end the test, click Disconnect Gmail, which deletes the saved sign-in from the computer. You can also remove access at Google Account permissions.

No account with the developer, payment or phone verification is needed at any point.

If the test inbox has no job emails

The scan only shows emails that look job-related, so an ordinary inbox may return nothing. Send these emails to the Google account you are testing with, from any other address, and run the scan again. All names are fictional. Each row shows what the scan should detect.

Trying the interface without Google

npm run demo starts the same app with sample jobs and a simulated mailbox. It never contacts Google, so it does not exercise the permission, but it is a quick way to see the screens.

What happens to the data

  • Email content is processed on the computer running the app and is not stored. The developer never receives it, and the app has no server.
  • Only the jobs the user chooses to add, email message IDs, and the Google sign-in token are saved, in a local database file on the same computer.
  • There is no analytics, no advertising, and no AI or machine learning.
  • The full details, including retention and deletion, are in the Privacy Policy, which includes the Limited Use statement.

Source code

The code is public at github.com/vedijapillay/job-tracker. The Gmail calls are in server/routes/gmail.js, and the only scope requested is set there.
